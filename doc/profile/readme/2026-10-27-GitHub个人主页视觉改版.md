## 2. 平台约束与组件调研

技术栈保持 README 的 Markdown / 允许的 HTML / SVG / PNG / GIF / GitHub Actions。没有引入 React、网页应用框架或需要浏览者执行的脚本。

[GitHub markup 官方说明](https://github.com/github/markup/blob/master/README.md) 明确 HTML 后续会清理内联样式、class/id 等内容。因此不能直接把网页 CSS 按钮粘进 README 并声称上传后仍然生效。本次采用 `<a><img /></a>` 图形按钮，样式写在独立 SVG 文件内部；仍是真实链接，能用键盘访问。

本轮实际查看并使用的项目：

- [Shields 静态徽章](https://shields.io/badges/static-badge)：支持图形链接、颜色与图标参数；参考其 README 按钮思路，不直接混用多种徽章风格。
- [custom-icon-badges](https://github.com/DenverCoder1/custom-icon-badges)：参考以图标和图片承载 README 链接的方式。
- [GitHub Profile Summary Cards](https://github.com/vn7n24fzkq/github-profile-summary-cards#custom-colors)：采用其真实统计 SVG，已实测官方自定义配色参数生效。
- [GitHub Streak Stats](https://github.com/DenverCoder1/github-readme-streak-stats)：采用连续贡献信息与官方颜色选项。
- [lowlighter/metrics](https://github.com/lowlighter/metrics)：保留为可选公开活动补充，不再替代其他丰富统计。

没有复制第三方网页按钮代码或依赖其运行时。Stats 组件的两份 MIT 许可证已随包保存。

## 6. 自动刷新、Metrics 与故障保护

### 基础统计

`.github/workflows/profile-stats.yml` 每日 UTC 01:37（北京时间 09:37）及手动执行。脚本固定 GET 6 个公开源，无需新增用户 secret；写回使用 Actions 默认 token 和 contents:write。

`.github/scripts/refresh-stats.py` 先校验 HTTP、MIME、XML、统计字段、调色及不含活动内容，再用同目录临时文件原子替换。单卡失败保留旧图；派生图所需源无效时保留旧派生图。全部源失败时返回非零，不发布错误卡。

请求期间观察过个别 SSL EOF，重试后取得全部有效图，因此没有将上游服务可用性视为永久保证。

### 可选 Metrics

`.github/workflows/profile-metrics.yml` 使用用户可选的 METRICS_TOKEN，生成 base header/activity/community 与最近 30 天最多 4 条公开事件。没有添加需要其他账号的插件，也不再重复语言图。

METRICS 区初始为空，成功后只在该区增加补充图。其他六类统计全部位于标记区外。脚本只接受空区域或自身产生的卡，手动加入其他内容时拒绝覆盖。

两个工作流共用 profile-assets 并发组。生成期间默认分支前进时跳过提交；最后使用普通 push，由 Git 拒绝后续竞争。没有 force push、reset 或重写共享历史。

## 10. 2026-10-27：链接按钮层次与章节标题动效

### 目标与平台约束

用户选定增量：博客/邮箱链接更像精致按钮；`観測 · Insights` 与 `足跡 · Activity` 标题栏使用动态图片。后续视觉复核中用户指出 Activity 标题此前仍是静态图，并要求删除按钮箭头周围的圆与箭头上方短线。工作范围仍是 GitHub 个人主页 README，而不是独立网站。

[GitHub Markup 官方说明](https://github.com/github/markup) 提到 README HTML 会被清理，自定义内联样式、class/id 和脚本不能作为可靠交互层；[GitHub 图片渲染文档](https://docs.github.com/en/repositories/working-with-files/using-files/working-with-non-code-files) 说明 GitHub 上的 SVG 不支持动画。故按钮使用 SVG 图像本身的静态造型；标题使用受 GitHub 支持的 GIF，并通过 `<picture>` 为 `prefers-reduced-motion: reduce` 提供静态 SVG。

### 实施

- `tools/render-ui.py` 重绘两张图形按钮：保留细描边、顶边高光、下沿立体边、图标凹槽和内容分隔；移除箭头周围圆环及箭头上方短线，改用开放式箭头。沿用月白、墨黑、樱粉色。原博客和邮件 `href`、按钮图片的替代文本保持不变。
- `assets/ui/section-insights-keyframe.png` 与 `assets/ui/section-activity-keyframe.png` 分别从原 900 × 108 SVG 在 Chromium 中按原生尺寸渲染；`tools/build-insights-gif.py` 为两个标题生成 GIF，在不重排字形的前提下加入一枚低对比度花瓣慢速漂浮，并保留透明圆角。两张 GIF 均循环 4,320 ms、35 帧；Insights 为 8,907 字节，Activity 为 8,700 字节。
- 排查桌面预览中标题字形偶发消失：Pillow 解码抽帧仍能看到静态字形；将 GIF disposal 从清除前帧改为保留前帧后，Chromium 连续截图的标题字形保持可见，花瓣动画仍在变化。现象与清除式 disposal 对局部动画帧的合成影响一致，平台内部合成原因未单独验证。
- README 的两个 `picture` 在系统要求减少动态效果时分别选择原静态 SVG，普通模式显示对应 GIF。封面、标题文字、统计结构和贪吃蛇未改变。

### 验证与边界

- 在 Chromium 本地预览中，1440 px 与 390 px 下两个章节标题和按钮换行/缩放正常，没有横向溢出。
- 浏览器 `currentSrc` 实测：普通模式选择两个 GIF；模拟 `prefers-reduced-motion: reduce` 后选择各自静态 SVG。
- 两张按钮图在浏览器实际 SVG 渲染下检查了边框、图标、标题、邮箱和开放式箭头；两张 GIF 在 Chromium 桌面连续截图中标题字形可见、花瓣位置变化，另以 Pillow 检查尺寸、帧数、循环时长、透明圆角和文件大小。
- 本地预览没有复现 GitHub 全量渲染器/Camo；修改尚未推送，真实 GitHub 页面以及图片缓存需上传后观察。README 按钮是可点击链接，GitHub 上自定义 hover 仍不可实现；如果以后需要 hover 动效，需使用独立网页。
- GIF 会自动循环；系统减少动态效果通过 `<picture>` 选择静态图作为降动效方案。README 无法为 GIF 添加单独暂停控件。

本轮让两个入口更像同一套有边框与层次的导航控件，并为统计章节增加与既有樱花元素一致的轻量动势，同时保留静态标题、原始链接和减少动态效果的替代路径。
