只发送固定公开 GET，请求不包含用户 token，也不上传 README。最终配色下 6 张均得到 HTTP 200 + `image/svg+xml`，XML 根节点为 SVG，无 script：

| --- | --- | --- |
| profile-details.svg | 8,390 | 含 xie480、贡献趋势、公开仓库、加入时间和公开邮箱 |
| repos-per-language.svg | 3,271 | 原图例与 donut 比例保留 |
| most-commit-language.svg | 3,271 | 原图例与 donut 比例保留 |

请求期间 `repos-per-language` 的一次原主题请求、`most-commit-language` 的部分请求出现 SSL EOF。重试后最终目标配色的真实卡获取成功。来源服务存在缓存和请求时刻差异，例如 Profile 卡的贡献简写与 Streak 的总贡献不要求完全相同，不能为统一数字手动改值。

Summary Cards 官方说明：托管 API 的语言与 stats 卡汇总按 stars 排序的最多 100 个仓库，独立 GitHub Action 使用用户 token 可覆盖更多；本次采用其公开托管 API 口径，不将数据表述为 GitHub 全量官方统计。Streak 基于贡献图统计，不应当作 commit 数。

## 自动刷新候选

`refresh-stats.py` 使用标准库，只有脚本中写死的 6 个公开源。每个请求超时 35 秒；HTTP / MIME / SVG / 必需字段 / 调色 / active content 全部校验成功才原子替换对应文件。失败保留该卡旧图；4 张组合源中有坏文件时保留上次组合图。脚本向终端和 GitHub Step Summary 报告逐卡状态，不输出完整 SVG 或公开邮箱内容。6 项数据全部获取失败时返回非零状态。

工作流为 schedule + workflow_dispatch，每日 UTC 01:37（北京时间 09:37），`contents: write`；使用 `actions/checkout@v7` 和 `profile-assets` concurrency（应与其他写主页素材的工作流共用）。生成时默认分支前进则跳过发布；最后普通 push 拒绝非 fast-forward，无 force push / reset。

注意：GET 刷新免新增用户 secret，但仍依赖托管服务自身的配额与可用性。真正完全自托管生成需要按各项目官方 Action 配置自己的 token；本次没有为用户配置 secret，也未运行远程 Action。
